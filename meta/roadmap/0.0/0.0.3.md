# 0.0.3 — the harness, part 2 — PLANNED

> **Scope:** the remaining stages, the self-check that proves the harness can
> fail, and the tree checks that diff the library against the documents that
> describe it. **The self-check is the load-bearing half of this subcycle**: a
> suite that only ever agrees with what it is handed reports green while
> checking nothing.

## 1. Decisions taken at planning

- **P-15 — the exact-code rule from the start** (D-237, T-092). On the error
  channel, the SET of codes a rejection test reports must EQUAL the set its
  expectations name. The compiler ran the weaker subset rule for six cycles and
  found, when it tightened, that 17 of 131 files were reporting something
  nobody had asserted. Starting strict costs nothing; loosening later is
  impossible.
- **P-16 — a skipped stage prints a line saying it was skipped and why**
  (V-3). Silence is how a suite becomes green on a machine where it ran nothing.
- **P-17 — the tree checks run on every full invocation**, including the ones
  that currently have nothing to check. `check_no_owning_cells` over an empty
  set is the right answer and is what makes the check exist on the day the
  first cell type is written.
- **P-18 — `--only` prints, twice, that a filtered run concludes nothing**, and
  nothing is committed on the strength of one. The compiler's phrasing,
  adopted whole, for the same reason.

## 2. The stages added

| Stage | Tool | Passes when |
|---|---|---|
| `parse` | the compiler's `tools/parse_check` | every `.npk` in the tree is accepted with no diagnostic, each once |
| `accept` | the compiler's `tools/check` | accepted in silence |
| `check` | the compiler's `tools/check` | refused with **exactly** the expected codes |
| `device` | the built program | as `program`, but skipped loudly when no terminal is present |

The three tools come from the compiler's tree, built once per run from the
pinned checkout.

## 3. The self-check — the seven cases

`harness/selfcheck.py` constructs each case, runs the harness against it, and
requires a **failure**:

1. a `program` case whose `expect-exit` is wrong by one
2. a `check` case expecting a code the compiler does not report
3. a `check` case reporting a code no expectation names — the D-237 rule
4. a `golden` case whose bytes differ by one byte *(a stub until 0.7; the case
   exists now and is marked pending, so the day the stage lands the case is
   already written)*
5. a `golden` case whose bytes match but whose screen differs *(likewise)*
6. a `parse` case that does not parse
7. a generator whose output differs from the committed table by one line
   *(pending until 0.2)*

**Rule:** the self-check runs **first** in every full invocation, and a pending
case prints as pending rather than passing.
