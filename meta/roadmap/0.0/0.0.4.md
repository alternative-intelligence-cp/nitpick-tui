# 0.0.4 — `src/core/` — PLANNED

> **Scope:** `Vec<T>`, `Bytes`, `SmallMap<K,V>` and `limits.npk`. The three
> storage primitives T-006 decided to own rather than import, plus the one file
> every named bound lives in.

## 1. Decisions taken at planning

- **P-19 — `Vec<T>`'s block is `wild`, its lifetime its owner's scope.** The
  compiler's `List<T>` is `wild` for the compiler's own reason (its tables live
  as long as the process); ours is `wild` because the alternative — a managed
  `buffer` reinterpreted per element — would need a `=>!` per access, which is
  the unchecked reinterpretation the compiler's 1.4.2 found five latent
  instances of. One `=>!`, in one file, checked once, is the shape that
  survives. **Every `Vec` has a `vec_free` and every scope that made one calls
  it**, or `exit 0` traps under D-151 — which is exactly the enforcement wanted.
- **P-20 — `Bytes` is the only allocating string builder in the library.**
  `string_concat` allocates per call, and a frame is thousands of small pieces:
  the compiler measured exactly this shape as quadratic in `npkg`'s first full
  run, seventeen minutes of fifty-six spent in the kernel. Nothing in `ntui`
  builds output with `string_concat` in a loop, and a tree check would be
  worth adding if it ever appears.
- **P-21 — `put_uint` is allocation-free**, writing decimal digits into a
  stack array backwards and appending. Every escape sequence contains numbers
  and `int_to_string` allocates a `string` per call.
- **P-22 — `SmallMap<K,V>` is a linear scan over a fixed-capacity array**, and
  is not a hash map. Its sizes are tens; a linear scan over a contiguous array
  beats a hash at that size and has nothing to verify.
- **P-23 — every accessor's obligation is written now**, in the syntax it will
  take, as a comment, with a property test standing in
  (`specs/VERIFICATION.md` P-1). Deleting a comment marker in cycle 1.5 is a
  smaller change than inventing the clause then.

## 2. `Vec<T>`

```nitpick
pub struct:Vec<T> = { wild T->:items; int64:count; int64:cap; };
```

| Function | Contract (written as a comment now) |
|---|---|
| `vec_init<T>(cap)` | `ensures result.count == 0 && result.cap >= 1` |
| `vec_reserve<T>(v, need)` | `ensures v.cap >= v.count + need` |
| `vec_push<T>(v, move T:x)` | `ensures v.count == old(v.count) + 1` |
| `vec_pop<T>(v)` | `requires v.count > 0` |
| `vec_at<T>(v, i)` | `requires i >= 0 && i < v.count` |
| `vec_set<T>(v, i, move T:x)` | `requires i >= 0 && i < v.count` |
| `vec_truncate<T>(v, n)` | `ensures v.count == min(n, old(v.count))` |
| `vec_insert<T>(v, i, move T:x)` | `requires i >= 0 && i <= v.count` |
| `vec_remove<T>(v, i)` | `requires i >= 0 && i < v.count` |
| `vec_swap_remove<T>(v, i)` | `requires i >= 0 && i < v.count` |
| `vec_clear<T>(v)` | `ensures v.count == 0` |
| `vec_free<T>(v)` | `ensures v.cap == 0 && v.items == NULL` |

**Rule:** `vec_at` returns by value and is therefore for scalar `T` only —
for an owning `T` a copy is refused (TYPE-046), and the family reads through
`v.items[i]` at the site that knows the element's shape. This is the compiler's
own `List<T>` note, and the reason there is no generic `list_at` there either.

## 3. `Bytes`

```nitpick
pub struct:Bytes = { buffer:body; int64:len; };
```

Managed storage (a `buffer`, which drops at scope exit) rather than `wild`,
because a `Bytes` is per-frame and its reclaim should be automatic. Growth
doubles; `take()` hands the accumulated bytes out as an owned `string`;
`view()` hands a borrowed `uint8[]` for the write path.

## 4. `limits.npk`

Every named bound in one file, each with the specification rule that set it:

```
NTUI_ESC_TIMEOUT_NS      NTUI_PROBE_TIMEOUT_NS   NTUI_WRITE_TIMEOUT_NS
NTUI_IDLE_TIMEOUT_NS     NTUI_EVENT_RING         NTUI_CSI_PARAMS
NTUI_CSI_SUBPARAMS       NTUI_PARAM_MAX          NTUI_STRING_SEQ_MAX
NTUI_PENDING_MAX         NTUI_PASTE_MAX          NTUI_MAX_TIMERS
NTUI_GAP                 NTUI_EL_MIN             NTUI_CELL_INLINE
NTUI_READ_STAGING        NTUI_POST_QUEUE
```

`check_constants_named` (0.0.3) enforces that none of these numbers appears
anywhere else.

2. `Vec<T>` with its suite: both `T` shapes, every accessor at its boundary
