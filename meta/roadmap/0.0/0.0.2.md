# 0.0.2 — the harness, part 1 — PLANNED

> **Scope:** `harness/run.py` builds the library and judges a `program`-stage
> test by its exit code, at -O0 and again under `opt -O2`, with the toolchain
> pinned and the undefined-symbol scan as a build step. This is T-005's runner
> and it retires into `npkg` when O-N2 closes.

## 1. Decisions taken at planning

- **P-10 — the harness reads `nitpick.toml` and never hardcodes a path.**
  Entry, output, opt-level, the four flag lists, and the `[[test]]` table all
  come from the manifest, for the compiler's own D-204 reason: a stated flag
  nothing consumes is the next stale document. The one thing it takes from the
  environment is `NPKC`, the compiler to test with.
- **P-11 — the undefined-symbol scan is a build step and fails the build**
  (`specs/BUILD.md` B-2), not a test that can be skipped. It reads the object's
  ELF64 symbol table directly rather than spawning `llvm-readelf`: a fourth
  tool outside the pin, whose text output nothing checks, is a poor foundation
  for a rule that is law. Python's `struct` module reads an ELF symbol table in
  about forty lines.
- **P-12 — the allowlist is derived, not written.** It is every `define` in
  `runtime/npkrt.ll` plus `main`. A written list goes stale the first time the
  floor gains a symbol.
- **P-13 — `opt -O2` is a check leg on every program, always**
  (`specs/BUILD.md` B-3). The compiler's own version of this instrument found a
  real defect on its first run that had passed for six cycles. A missing `opt`
  fails loudly rather than skipping.
- **P-14 — one build of the library per run, reused by every program.** The
  library compiles once to an object; each test program compiles and links
  against it. A per-test rebuild is the difference between a two-minute suite
  and a forty-minute one, and it is worth getting right now.

## 2. The pipeline

```
manifest ─► module graph ─► npkc  ─► ntui.ll
                                  ├─► opt -O2 ─► ntui.opt.ll     (check leg)
                                  └─► llc      ─► ntui.o
                                          └─► ELF undefined-symbol scan
per program: npkc ─► p.ll ─► llc ─► p.o ─► scan ─► ld.lld(p.o, ntui.o, npkrt.o) ─► run
```

## 3. Steps

1. **`harness/manifest.py`** — a minimal TOML reader (the manifest is small and
   the format's subset used here is a dozen lines), the schema check, and a
   loud refusal naming any key the schema lacks.
2. **`harness/toolchain.py`** — asks `llc --version`, `opt --version`,
   `ld.lld --version` and refuses a mismatch against `[toolchain] llvm`. Asks
   the tools, not `llvm-config`, which is a `-dev` package the build does not
   need.
3. **`harness/elf.py`** — the ELF64 symbol-table reader and the allowlist
   derivation from `runtime/npkrt.ll`.
4. **`harness/build.py`** — the pipeline above, every argv built from the
   manifest's flag lists.
5. **`harness/stages.py`** — the `program` stage: read `// expect-exit:`,
   `// stress: N` and `// argv:` from the file; run; compare; repeat under the
   optimised object.
6. **`harness/run.py`** — the driver: stage order, per-unit verdict lines,
   `--only`, `--verdicts PATH`, and a summary that states the counts.
7. **The `repro` check** — build twice from two working directories, compare
   the emitted `.ll` byte for byte, fail loudly on a difference. Reproducibility
   is a tested property or it is not a property.
8. **One real program** — `tests/probe/probe03_pod_array.npk` from 0.0.0, run as a
   `program`-stage entry, green under both legs.

## 4. Acceptance

- [ ] `python3 harness/run.py` builds the library and runs the probe suite
- [ ] every program runs at -O0 and under `opt -O2` with the same exit
- [ ] a deliberately introduced undefined symbol fails the **build**, by name
- [ ] a toolchain-version mismatch refuses loudly
- [ ] `--verdicts out.txt` writes one line per unit
- [ ] the `repro` check is green and has been seen to fail (by hand, once, with
      a deliberately non-deterministic edit) — a check that has never failed has
      never been shown to work
